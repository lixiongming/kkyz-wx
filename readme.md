# ziniu-wk

uniapp 的开发框架

# 分层架构设计

## views 视图层
用于处理用户的交互，所有可视页面、表单、动画、交互等等。

## business 业务层
实现企业核心业务逻辑，通过各种校验手段保证业务的正确性。业务层主要体现领域模型的业务能力，它来表达业务概念、业务状态和业务规则。


## infrastructure 基础层
基础层是贯穿所有层，它的作用就是为其它各层提供通用技术和基础服务，包括第三方工具、驱动、消息中间件、网关、文件、缓存、以及文件管理。


## 技术选型
* UI框架 [uView 3.2.23](https://uview-plus.jiangruyi.com)
  - 踩坑(ui组件不能使用up-当前缀，而是使用u-开头，框架地址组件示例是使用up-开头)

## pages.json的模块化
- 请确保安装相关依赖: npm install
- 将pages.json 文件迁移到pages.js文件内
- /business/routes/pages.js 为pages模块化核心逻辑，在该文件可以修改 首页
- /business/routes/page_modules/ 为子page, 可以自定义文件。

## utils文件夹用于存放通用的工具函数和模块
- chat-types.js 为聊天类型常量
- check-reg.js 为常见的正则

## api遵循单一入口文件原则
- modules 存放各个模块的api
- index 入口文件 添加命名空间导出
- import { 命名空间 } from "@/business/api" 导入使用

## 页面顶部导航栏
- 已处理页面内容区域滚动不影响触发onReachBottom事件
- 使用 g-main 组件，传入gTitle作为标题
- 导航左侧图标可自定义，slot为left
- 导航右侧图标可自定义，slot为right

## 文件命名规范
- 例：video-info.nvue
      video-info.ts

## pages目录结构
- 分五个主模块 home、explore、message、mine、publish
- 各模块主页面直接写于文件夹一级
- 各模块通用页面/组件，写于文件夹compoennts
- 全局通用组件写于全局compoennts

## 后端常见状态码
> 通用http-code

- 200   成功
- 500   业务异常，一般逻辑验证不过抛出 
- 400   客户端错误请求
- 401   token已失效
- 404   文件不存在
- 405   http请求跨域
- 406    token无效（被挤掉或者已退出）
- 407    进行切换账号，token已失效
- 1000    手机号已注册
- 1001    手机未注册
