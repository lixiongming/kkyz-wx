# 移除 pca-code-min.json 文件，使用接口获取位置信息方案

## 分析当前状态
通过分析当前代码和参考修改地址页面的实现，了解到：

1. **getCityV2Api 接口**：`mall/address/city` 接口接受一个 `pid` 参数，当 `pid` 为 0 时返回所有省份列表，当 `pid` 为某个省份/城市的 id 时返回其下一级的城市/区县列表
2. **接口返回格式**：接口返回的数据格式为数组，每个元素包含 `id`、`name`、`parent_id` 等字段
3. **当前使用 pcaData 的地方**：
   - 初始化省份列表：`init_province_list()` 函数
   - 获取用户位置：`getUserLocation()` 函数
   - 初始化城市列表：`init_city_list()` 函数

## 修改计划

### 1. 移除 pcaData 导入，添加 API 调用
- 移除 `import pcaData from '@/static/json/pca-code-min.json';`
- 添加 `import { getCityV2Api } from '@/business/api/modules/api-new';`
- 添加必要的加载状态和数据缓存

### 2. 修改 init_province_list 函数
- 将函数改为异步函数
- 使用 `getCityV2Api({ pid: 0 })` 获取省份列表
- 处理接口响应，生成省份列表数据
- 添加加载状态和错误处理
- 添加数据缓存，避免重复请求

### 3. 修改 init_city_list 函数
- 将函数改为异步函数
- 根据选中的省份，使用 `getCityV2Api({ pid: provinceId })` 获取城市列表
- 处理接口响应，生成城市列表数据
- 添加加载状态和错误处理
- 添加数据缓存，避免重复请求

### 4. 修改 getUserLocation 函数
- 保持函数基本结构不变
- 修改城市查找逻辑，使用 API 获取的数据
- 添加错误处理，确保在 API 调用失败时仍能使用默认城市

### 5. 修改 select_location 函数
- 确保在打开城市选择弹窗前，省份和城市数据已加载完成
- 添加加载状态提示

### 6. 修改 onMounted 函数
- 调整初始化顺序，确保在获取用户位置前，省份和城市数据已加载完成
- 添加异步处理，确保初始化过程顺利完成

### 7. 移除 pca-code-min.json 文件
- 在确认所有功能正常后，移除 `static/json/pca-code-min.json` 文件

## 预期结果
- 成功移除 pca-code-min.json 文件，减少主包体积
- 使用接口获取位置信息，数据更加实时准确
- 所有位置相关功能正常工作
- 代码结构清晰，错误处理完善
