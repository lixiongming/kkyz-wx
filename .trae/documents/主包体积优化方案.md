# 主包体积优化方案

## 问题分析
通过分析项目结构和配置，发现主包体积过大的可能原因：

1. **代码包过大**：主包中包含了多个页面和组件
2. **依赖包过大**：项目使用了多个依赖包，如 animate.css、html2canvas、lodash 等
3. **静态资源过大**：可能包含过多或过大的静态资源
4. **未优化的导入**：存在未使用的导入或重复导入
5. **pcaData 数据**：中国省份城市数据是一个体积较大的 JSON 文件

## 优化方案

### 1. 分包优化
- 将更多非核心页面移到分包中
- 具体操作：
  - 将 `views/pages/save-money` 相关页面移到新的分包
  - 将 `views/pages/mine` 相关页面移到新的分包
  - 确保只有核心的 tabBar 页面留在主包

### 2. 依赖优化
- 移除或替换不必要的依赖包
- 具体操作：
  - 评估并移除未使用的依赖
  - 使用更轻量的替代方案，如使用 dayjs 替代 moment
  - 按需导入依赖，避免全量导入

### 3. 静态资源优化
- 压缩图片和其他静态资源
- 具体操作：
  - 使用图片压缩工具优化静态图片
  - 考虑使用 CDN 加载部分静态资源
  - 实现图片懒加载

### 4. 代码优化
- 移除未使用的代码，使用动态导入
- 具体操作：
  - 清理未使用的组件和函数
  - 继续使用之前的 pcaData 动态加载方案
  - 实现组件的按需加载

### 5. 构建优化
- 配置构建工具，优化打包过程
- 具体操作：
  - 配置 Vite 或 Webpack 进行代码分割
  - 启用 tree-shaking 移除未使用的代码
  - 配置生产环境的压缩和优化选项

## 预期效果
通过以上优化措施，预计可以显著减少主包体积，使其能够正常打包。同时，优化后的代码结构也将更加清晰，有利于后续的维护和开发。
